# 销售成交方法论手册

## 当前版本只保留的主方法

`dsh-sales` 不同时引入一整套销售流派。当前只保留四个最小方法包：

1. `JTBD / Value Proposition`：承接 `dsh-idea`、`dsh-product` 已确认的问题和价值；
2. `SPIN / Gap Selling`：用于沟通时把现状、问题、影响和结果问清楚；
3. `MEDDICC / SPICED`：用于资格判断和商机退出条件；
4. `Value Selling + Mutual Action Plan`：用于报价、谈判、成交和交接。

`Challenger`、`Sandler`、`BANT` 等只作为可选参考，不单独增加工具或阶段。价格和利润不在本手册内重新计算，使用 `dsh-business` 的现有工具。

## 证据等级

每个销售输入标记为：

- `observed`：系统或文件中的可核验事实；
- `customer-stated`：客户明确说过或书面确认的内容；
- `estimated`：团队估计，必须保留假设；
- `inferred`：根据证据推断，不能写成客户承诺；
- `missing`：没有证据，转成下一步验证任务。

## 资格判断

资格判断不是给客户贴标签，而是回答“这笔机会是否值得投入，以及最小验证动作是什么”。建议至少覆盖：

1. Problem：问题是否真实且有代价；
2. Impact：问题是否能连接到业务结果；
3. Buyer：谁受影响、谁决策、谁批准；
4. Process：采购、技术、法务和上线流程是什么；
5. Timing：为什么现在，下一日期是什么；
6. Competition：客户当前替代方案是什么；
7. Commitment：客户是否完成了可验证动作。

在当前插件体系中，资格判断的最小结果不是“客户质量分”，而是四选一：`advance`、`validate`、`hold`、`disqualify`。任何评分都必须回到缺失证据、客户动作和下一日期。

## 商机阶段

阶段必须用退出条件定义，而不是用销售主观感受定义。一个阶段至少包含：进入条件、必须证据、客户动作、销售动作、退出条件、Owner、预计日期和停止规则。

## 报价与变现

报价审查至少要分开：价值、标价、成交价、折扣、成本、渠道费用、贡献毛利、付款条款和授权。没有 `dsh-business` 或用户提供的价格边界时，只能识别缺口和风险，不能替用户决定价格。

实际使用顺序是：先用 `business_pricing_review` / `business_profitability_review` 判断能不能卖，再用 `sales_offer_review` 判断客户是否买得成；两者都通过才进入成交计划。

## 预测

加权预测是金额乘以阶段概率的估计，不是收入承诺。必须同时展示：原始管道、加权管道、预计成交窗口、阶段概率来源、过期商机、缺少金额或成交日的记录，以及最可能改变预测的证据。

## 复盘

成交复盘不要只记录“赢 / 输”。要记录触发事件、客户结果、关键证据、竞争或替代方案、阶段停留、未兑现承诺、决策人变化、失单原因和下一次改变的动作。
